At a glance — what this paper contributes and what to lead with

The headline finding

How hard a task is — measured by how many of four agents solved it — accounts for 60% of whether any given agent succeeds or fails. The kind of bug (logic fix, exception handling, config change, etc.) accounts for 1%. That is a 47-fold difference. The two-panel figure showing this is the paper's most important visual and should be the first data shown in any talk or abstract.

This matters because most prior work characterizes tasks by their semantic type — the kind of bug — and treats that as a meaningful grouping. It is not. Structural edit complexity, which is visible in the shape of the oracle patch before any agent runs, is what actually determines success.

The structural finding that closes the circularity

Difficulty, if measured only by agent outcomes, is circular. We have three independent operationalizations that converge: (1) n_resolved, the fraction of our four agents that solved each task; (2) the 84-agent ease score from the full SWE-bench Lite leaderboard, which correlates with n_resolved at r = 0.76; and (3) fill-in-the-middle (FIM) patterns on the oracle patch itself — readable before running any agent. Hard tasks have patches that introduce conditional logic and new function calls. Easy tasks swap a return value or reassign a variable. This structural grounding is the ICSE-level contribution.

The secondary finding — two independent axes

Difficulty and agent identity explain different things and neither explains the other. Difficulty predicts whether an agent succeeds. Agent identity predicts how the agent works — GPT models use shorter, more compressed action sequences; Claude models use longer, more exploratory ones. These behavioral signatures are stable across tasks and task types. Knowing which model ran a trajectory tells you little about whether it succeeded, but tells you a lot about what it did procedurally.

What we built (methodological contributions)

  • A behavioral vocabulary for agent trajectories. We apply byte-pair encoding to the action sequences of 1,162 trajectories, discovering 125 compound motifs from 76 primitive actions. The vocabulary is justified by minimum description length — it is not an arbitrary clustering but the shortest lossless description of what agents did. Compression ratio (motif sequence length / atom sequence length) is a well-defined, model-free measure of how much an agent repeats itself.
  • A multi-predictor, multi-outcome MI decomposition. Mutual information in bits, normalized to percentage of outcome uncertainty removed, gives a single comparable number across binary outcomes (pass/fail) and continuous ones (trajectory length, compression). This is more coherent than eta² because it does not assume linearity and uses consistent units across all nine predictor-outcome pairs.
  • A failure anatomy. Between 57% and 73% of all failures — depending on the agent — are Type B: the agent found the right file but could not fix it. Type A failures (never found the file) are the minority. This reframes where effort should go: better navigation is not the bottleneck.

How to order these in a talk (20 minutes)

  1. 5–7 min: The 47× gap. Show the difficulty panel and the fix-type panel side by side. Let the contrast land. Give the 60% / 1% numbers. Ask: why does the thing everyone uses to characterize bugs explain almost nothing?
  2. 3–4 min: FIM patterns. Explain that the answer is visible in the patch itself, before running any agent. Show three examples — a hard pattern, an easy pattern, a fully unsolved one. This is the structural grounding that makes the claim non-circular.
  3. 3–4 min: The two-axis decomposition. Show the MI decomposition figure. Difficulty explains success; agent explains style. Neither explains the other. This is why agent comparisons without difficulty control are noise.
  4. 2–3 min: Behavioral fingerprinting. Brief: GPT agents compress more, Claude agents explore more. The vocabulary exists. The motif grammar is learnable.
  5. 2–3 min: So what. What a centaur interface looks like. What the gym experiment would test. Why model diversity (RL-trained vs SFT-trained) is the next stress test.

What is secondary (do not lead with)

  • Cost per resolved task — interesting but downstream of the main finding; mention as a practical implication, not a headline.
  • Variance decomposition (SD ratio across 10 features) — methodologically solid but a supporting result, not the lead.
  • BPE mechanics (merge count, vocabulary size) — belongs in a methods section or appendix, not the opening.
  • Fix type by agent — shows the signal is weak for all agents uniformly; useful as a robustness check, not a contribution.

0. Research framing and argument structure Appendix

Core thesis. Current agent benchmarks conflate semantic task category (what kind of bug it is) with structural edit complexity (how hard the patch is to write). Structural complexity — derivable from the oracle patch before running any agent — predicts agent failure with high fidelity. Semantic category predicts almost nothing. Knowing task difficulty removes 60% of outcome uncertainty; knowing fix type removes 1%.

The argument in three levels

Level 1 — Empirical (workshop paper). Across 1,162 trajectories and 4 agents, difficulty (how many of the 4 agents solved each task) accounts for 60% of outcome uncertainty (MI = 0.40 bits). Fix type (logic fix, exception handling, API change, etc.) accounts for 1% (MI = 0.01 bits). This is not a subtle effect: the 47× gap is visible by inspection in the figure.

Level 2 — Validated. The 4-agent difficulty proxy (n_resolved) correlates with the 84-agent ease score from the full SWE-bench Lite leaderboard at Spearman r = 0.76. The proxy captures the difficulty signal but is not identical to intrinsic hardness. Importantly, n_resolved = 0 does not mean "impossible" — many such instances have 84-agent ease up to 0.81. The difficulty axis reflects agent capability, not intrinsic task hardness.

Level 3 — Structural (ICSE core claim). Difficulty traces back to edit complexity of the oracle patch, identifiable via FIM (fill-in-the-middle) patterns before running any agent. Hard patterns (ease ≈ 0.02): conditional checks with comparisons and new function calls. Easy patterns (ease ≈ 0.67–0.81): return-value swaps, variable reassignments. Fully unsolved (ease = 0.00): algorithm replacement + import + signature change. Fix type is a semantic label that does not capture edit complexity — which is why it has near-zero predictive power.

Why MI rather than eta²

The primary variance attribution metric is mutual information (MI) in bits, not eta². The GQM chain justifies this: Goal → attribute outcome uncertainty to predictors; Question → how much of pass/fail uncertainty does knowing X remove?; Metric → I(X; Y) in bits. This is the most coherent choice because the paper already works in an information-theoretic register (entropy of motif distributions, Jensen-Shannon distance between agents, MDL as the justification for BPE). Framing the finding as "difficulty removes 60% of outcome uncertainty" is also more interpretable to a cold reader than "eta² = 0.56."

Robustness: omega² (bias-corrected eta²) = 0.558 ≈ eta² = 0.560 — bias is negligible at n = 1,162. Both tell the same story. These are in the appendix.

Measurement validity chain

Following Campbell & Fiske (1959) and Cronbach & Meehl (1955), every empirical claim rests on a construct → indicator → operationalization chain:

  • Construct: "how hard is this task for agents"
  • Primary indicator: n_resolved (fraction of our 4 agents that solved it). MI(n_resolved; pass/fail) = 60.2% of H — the headline finding.
  • Cross-population check (load-bearing for non-circularity): 84-agent leaderboard ease, an independent agent population. Spearman r = 0.76 with n_resolved.
  • Interpretive structural surface: FIM edit patterns on oracle patch. MI(FIM-form; pass/fail) = 19.4% of H. Useful for narrative ("15 named patterns describe the patches"); does not add independent quantitative weight beyond n_resolved (conditional MI ≈ 0).

The key insight: n_resolved is partly circular by construction but generalizes across an independent agent population (the 84-agent leaderboard). The non-circularity defense rests on this cross-population replication, not on a structural-foundation argument. Simple problem-side and patch-shape features explain only a fraction of the difficulty signal — the 60% MI captures latent structure that single observable features don't recover.

Empirical evidence that saves the circularity argument. n_resolved = 0 for 196/300 instances — all agents failed — making 65% of trajectories floor-determined. The 60% MI figure is partly driven by this structure, which is real but not clean. Within the uncertain bins (1/4, 2/4, 3/4), trajectory length does not predict pass/fail (r = −0.12 to −0.17, non-significant in 2 of 3 bins) — so the signal isn't just "tasks that took more steps." The 84-agent leaderboard provides the cross-population check at r = 0.76. Empirical tests of structural surrogates (FIM-form: 19.4% MI; AST-edit complexity: ρ = −0.27 with ease, dominated by patch LOC at ρ = −0.36; problem-side text features: all < 2% MI) show the difficulty signal is not reducible to single observable features — it lives in latent structure that aggregate-agent measurement captures but surface features do not.

Research framework applied

For every method choice, the following framework is applied in order:

  1. Construct validity — does the indicator validly measure the latent construct? Convergent and discriminant validity checks required.
  2. GQM — Goal → Question → Metric. The metric must be traceable to a goal; otherwise it is unjustified convention.
  3. Falsificationism — state the claim being tested and what result would falsify it. The permutation null (p < 0.001) and the MI comparison (60% vs 1%) are both falsification tests.
  4. Lakatos — hard core: difficulty predicts agent success; semantic category does not. Protective belt: which difficulty measure, which metric. Hard core stands across all operationalizations.
  5. Causal inference — this is observational data. Claims use "predicts" / "is associated with" / "accounts for," not "causes."

0.6 Concept glossary with references Appendix

Canonical atom

The smallest unit in our action vocabulary. Raw agent actions (bash commands, file edits, search queries) are parsed into typed, normalized units. Type tags retain semantic content; literal strings (exact filenames, search terms, line numbers) are stripped, so that two edits to different files map to the same atom. 76 atom types in total.

Why strip literals? Because we want to ask "did this agent search, then open a file?" not "did it search for this exact string?" Two trajectories that navigate differently but perform the same structural sequence should be recognized as using the same pattern.

Raw actionCanonical atomWhat was stripped
edit /repo/src/utils.py lines 42–58EDIT_SRC_PYfilename, line numbers
grep -r "KeyError" /repo/SEARCHsearch term, path
python /repo/reproduce_bug.pyRUN_PYTHON_REPRO_PYexact path
pytest tests/test_parser.py -vRUN_TESTtest file, flags

Inspired by OverCode's canonicalization of student code before clustering (Glassman et al., 2015).

BPE (Byte Pair Encoding) motif

BPE was originally a text compression algorithm (Gage 1994, repurposed for NLP tokenization by Sennrich et al., 2016). Applied to agent trajectories: start with the 76-atom vocabulary; iteratively find the most-frequent adjacent pair and bind it into a new compound unit. After 125 merges the vocabulary contains 125 compound motifs on top of the 76 atoms. Compression factor: 0.42 (a BPE sequence is 42% as long as the atom sequence).

Why BPE? Because it finds the sub-sequences that most compactly describe the corpus — the Minimum Description Length (MDL) principle. The motifs that survive to the top of the merge list are the patterns the corpus "wants" to use. This aligns with DreamCoder's library-induction-via-compression approach.

Step-by-step example — the first merge actually performed:

StepSequence
Atom sequence (before merge 1) SEARCH   NAV_SRC_PY   EDIT_SRC_PY   EDIT_SRC_PY   RUN_TEST
Most frequent pair (800+ occurrences) EDIT_SRC_PY + EDIT_SRC_PY
After merge 1 SEARCH   NAV_SRC_PY   EDIT_SRC_PY×2   RUN_TEST
After 125 merges (example motif) EDIT_SRC_PY + RUN_TEST + EDIT_SRC_PY  = "edit-test-edit loop"

MDL justification: DreamCoder (Ellis et al., 2021). NLP tokenization: Sennrich et al. (2016).

Mutual information (MI)

I(X; Y) = H(Y) − H(Y|X), measured in bits. Tells you how much uncertainty about Y is removed by knowing X. Model-free: no distributional assumptions about the shape of the relationship.

Intuition: H(Y) is the total uncertainty about whether a trajectory passes. MI(X; Y) is what fraction of that uncertainty is explained by knowing X. If MI = 0, X tells you nothing about Y. If MI = H(Y), X tells you everything.

JSD (Jensen-Shannon Distance)

A symmetric, bounded (0 to 1) measure of divergence between two probability distributions. JSD = √(JS divergence), where JS divergence = ½KL(P||M) + ½KL(Q||M) and M = (P+Q)/2. Used here to compare two agents' motif usage distributions.

Why JSD? (a) Symmetric — swapping agent A and agent B gives the same answer. (b) Bounded in [0, 1] — comparable across runs. (c) Finite even when one agent never uses a motif the other relies on (raw KL divergence would be infinite in that case).

Type A / Type B failure

Every failing trajectory falls into one of two categories based on whether the agent ever visited the gold file (the file the oracle patch modifies).

Type A — Navigation failure
Agent never opened or edited the gold file. It could not localize the bug. Often caused by misleading error messages or insufficient search coverage.
Claude-3: ~50% of failures
GPT-4o: ~39% (25% clean-exit)
Claude-3.5: ~28%
GPT-4: ~26%
Type B — Implementation failure
Agent reached the gold file but did not produce a passing patch. Localization succeeded; the edit was wrong or incomplete.
Remaining failing trajectories after type A.
Wide IQR in post-localization steps for Claude-3.5 and GPT-4o suggests high variance in what agents try after finding the file.

Note on budget cuts: GPT-4o trajectories terminated by token budget (39% of all GPT-4o runs) inflate type A counts — an agent that was mid-search when cut is scored as "never reached." Clean-exit-only analysis drops GPT-4o type A to 25%.

Eta² (eta-squared) and omega²

eta² = SSbetween / SStotal from one-way ANOVA. Proportion of total sum of squares explained by the grouping variable. Bounded [0,1]. omega² = (SSbetween − (k−1)·MSwithin) / (SStotal + MSwithin) corrects for finite-sample bias. At n = 1,162, omega² ≈ eta² (0.558 vs 0.560). Both are in the appendix as robustness checks. MI is the primary metric in the main body because it is coherent with the paper's information-theoretic vocabulary and makes no distributional assumptions about the binary outcome variable.

Budget cut (exit_cost)
A trajectory terminated because the agent hit the token budget limit rather than voluntarily submitting. Budget-cut trajectories inflate type A counts. GPT-4o is most affected: 39% of its trajectories are budget-cut; clean-exit type A rate drops from 39% to 25%.
Novelty index

For each motif used by agent A: novelty = log₂((pagent + ε) / (pcorpus + ε)). Positive = over-uses relative to corpus average; negative = under-uses. Top novelty motifs are the agent's procedural fingerprint.

Construct validity
A measurement is construct-valid if it genuinely measures the latent construct it claims to measure. Two key tests: convergent validity — different operationalizations of the same construct should agree (here, n_resolved and 84-agent ease correlate at r = 0.76); discriminant validity — the measure should not correlate with measures of different constructs (here, n_resolved is uncorrelated with repository size or number of files changed). Reference: Campbell & Fiske (1959).
Procedural motif vs semantic label

The core distinction in this paper: a procedural motif is what the agent did (sequence of typed actions); a semantic label is a human categorization of the task type. Fix type (logic fix, exception handling, API change, etc.) is a semantic label. BPE motifs (SEARCH → OPEN_SRC, EDIT → RUN_TEST → EDIT) are procedural patterns. The paper's central finding: semantic labels have near-zero predictive power (MI = 0.01 bits), while structural task difficulty — which correlates with procedural complexity of the oracle patch — explains 60% of outcome uncertainty.

0.8 Anticipated reviewer concerns Appendix

Each concern is framed around why it would matter — what it would mean for the paper's central claims if it were valid — followed by where we currently stand and what work remains.

R1 — The difficulty measure is circular

A reviewer will notice that n_resolved is computed from the same agent outcomes we use it to predict. If an agent failed, n_resolved for that task is lower; if it passed, higher. Predicting pass/fail from a variable derived from pass/fail is not a clean finding — it could be tautological, and 65% of trajectories sit in floor or ceiling bins where n_resolved perfectly determines outcome by construction.

Why this matters: If the circularity is real, the 60% MI figure is inflated and the headline finding collapses.

Where we stand (revised after empirical test): The primary non-circularity defense is the 84-agent leaderboard ease — an independent agent population from our 4-agent corpus. Spearman correlation between n_resolved (4-agent) and 84-agent ease is r = 0.76, so the difficulty signal generalizes across agent populations rather than being a function of which agents we tested. Within-bin trajectory-length analysis adds: even controlling for difficulty stratum, length r = −0.12 to −0.17 (non-significant in 2 of 3 uncertain bins), so the signal isn't just "tasks that took longer."

Where the structural argument actually landed: FIM-form (patch-derived AST shape) carries MI = 19.4% on pass/fail — real signal, but a third the strength of n_resolved (60.2%). When we condition on n_resolved, FIM-form's marginal MI drops to 0.3% — FIM is largely captured by what n_resolved already encodes. AST-edit complexity is also dominated by patch LOC for predicting ease (ρ = −0.27 vs ρ = −0.36, collinearity 0.53). Simple problem-side text features (has_reproducer, issue length, code-block count, has_failing_test mention) all explain < 2% of pass/fail uncertainty individually.

Honest framing: The 60% MI on n_resolved captures real, non-trivial difficulty that is not cleanly traceable to any single observable feature of the patch or the problem statement we tested. The aggregate-agent signal aggregates something deeper — likely repository structure, module coupling, and conceptual complexity — that surface features don't recover. The non-circularity claim rests on the 84-agent cross-population check (r = 0.76), not on a structural-foundation argument. FIM-forms remain useful as an interpretive surface (15 named patterns) but do not carry independent quantitative weight beyond n_resolved.

R2 — All agents use the same scaffold

Every agent in the core corpus runs on SWE-agent. A reviewer will argue that behavioral differences between Claude and GPT families might reflect how each model interacts with SWE-agent's specific prompting and tool interface — not anything intrinsic to the model. Put differently: you cannot separate model from scaffold when every model uses the same scaffold.

Why this matters: If the scaffold drives behavioral patterns, the "agent behavioral fingerprint" finding is a scaffold artifact, not a model property.

Where we stand: This concern is substantially addressed. Section 13 presents a direct comparison: the same Claude-3.5 Sonnet backbone run on both SWE-agent and Agentless, on the same 300 tasks. Phase categories (localize, repair, verify) transfer across scaffolds. Phase emphasis does not — SWE-agent spends 65–69% of trajectory on repair; Agentless spends 50–60% on localization. This shows the scaffold shapes the procedural distribution but the underlying phase grammar is model-stable. The confound is real but not fatal: scaffold and model are separable, and we have the paired comparison to show it.

What remains: The scaffold × backbone factorial is partial. We have SWE-agent × {GPT-4, Claude-3.5, GPT-4o} and Agentless × Claude-3.5. Completing the factorial with Agentless × GPT-4 and GPT-4o would allow a clean scaffold effect estimate. This is follow-on work.

R3 — Fix type labels may be unreliable

The MI(fix type; pass/fail) = 1% finding depends on the fix type labels being a valid characterization of task semantics. If the labels are noisy — assigned by a single annotator without validation — the 1% figure might reflect measurement error rather than a real signal. A reviewer cannot distinguish "fix type genuinely predicts nothing" from "the labels are too noisy to measure any real signal."

Why this matters: The 47× gap (difficulty vs fix type) is only meaningful if fix type is a legitimate measure. A poorly labeled taxonomy weakens the comparison.

Where we stand (documented): Labels are LLM-automated via a FixTypeModule (DSPy pipeline) applied to AST-extracted edit certificates and patch diffs. The field name fix_type_hand implies human review at some point, but scripts/discover_fix_forms.py contains no annotation logic — it loads pre-existing labels as ground truth and treats them as a fixed classification. n=289 instances labeled: logic_fix (142), exception_handling (34), api_change (27), config_fix (20), guard_clause (17), refactor (13), string_fix (11), type_coercion (11), test_fix (5), other (4), import_fix (3), async_fix (1), loop_fix (1). No multiple-annotator process and no inter-rater reliability measurement are documented.

What remains: The MI(fix type; pass/fail) = 1% finding is not heavily load-bearing — the paper's core claim is that fix type is a weak predictor. A noisy automated label would only attenuate the signal toward zero, which strengthens rather than weakens the "1% is real" reading. If a reviewer presses, the response is: (1) the labels are programmatically derived from patch structure, not subjective human judgment; (2) 1% is an upper bound if the labels are noisy — the true signal is at most this; (3) the FIM pattern analysis, which uses oracle patches directly, does not rely on these labels. No Cohen's κ is needed because the claim direction is robust to label noise.

1. Scope and methodology Headline

Paper 2 investigates procedural variation among software-engineering agents through two complementary layers: action-sequence analysis (what each agent did, step by step) and rationale-based preference analysis (what distinguishes agents qualitatively). Today's pilot covers the action-sequence layer.

Data

  • 867 raw .traj trajectories fetched from the public SWE-bench submissions bucket
  • 3 SWE-agent variants: GPT-4, Claude 3.5 Sonnet, GPT-4o (same scaffold, different backbones)
  • SWE-bench Lite (300 instances)
  • 99 tied-outcome pairs where two agents both resolved the same task

Committed methodology

Canonicalize-then-BPE: parse raw shell-like actions into canonical atoms (type-tagging file paths, stripping non-semantic literals), then run BPE on the canonicalized sequences to discover emergent procedural motifs. Bottom-up vocabulary, aligned with OverCode's canonicalize-before-cluster recipe and Ellis/DreamCoder's library-via-compression lineage. If any unfamiliar terms appear below (BPE, canonical atom, motif, JSD, "procedurally permissive"…), the Glossary at the end defines them.

Data provenance: raw trajectories cached at output/trajectories/.cache/ with per-file SHA-256 manifest and human-readable NOTE.md describing the fetch run.

2. Phase A — pilot on hand-coded 8-token DSL (scaffolding) Appendix

The pre-extracted SWE-agent parquets collapse each trajectory's actions into an 8-token DSL (CREATE, EDIT, NAV, OPEN, OTHER, RUN, SEARCH, SUBMIT). Phase A uses this DSL directly as scaffolding. Findings here motivate the full methodology; they are preliminary and will be replaced by Phase B results for the paper.

2.1 Variance decomposition across 1,162 trajectories

Task identity drives feature variation more than agent identity. For 8 of 10 per-trajectory features, the SD of task-means exceeds the SD of agent-means (ratio > 1). Searches (4.1×) and edit retry rate (3.2×) are the most task-dominated. Holds on both full corpus (1,162 trajectories across 4 agents) and task-matched subset (262 shared tasks).

Interpretation: at the level of raw action counts, what an agent does depends more on the task than on which agent is solving it. Agent style does not live in count features. This motivates the rollout-layer analysis in Phase B.

2.2 Pair Levenshtein on tied-outcome pairs (99 pairs)

Within-task sequence divergence is substantial and shows model-family heritability. Same-family agents (GPT-4 and GPT-4o) have mean Levenshtein 0.37 on tied-outcome pairs; cross-family pairs are 0.51–0.52. Preliminary evidence that model-family drives rollout-level style.

2.3 Task-level procedural diversity

What "procedurally permissive" means. For each of the 300 SWE-bench Lite tasks, we compute the average pairwise sequence divergence among the agents that attempted it. A task is procedurally permissive if that divergence is ≥ 0.60 — i.e., on average, more than 60% of one agent's actions don't line up with another's, even when both succeed. A task is procedurally constrained if divergence is ≤ 0.30 — most agents follow nearly the same action path. "Pluralism" = most tasks are permissive: the benchmark doesn't force a single solution path.
Pluralism dominates: 47% of tasks are procedurally permissive, only 5% are constrained. Mean pairwise action-sequence divergence across 300 tasks is 0.58 (median 0.59). All-resolved tasks diverge less (median 0.48) than mixed-outcome tasks (0.60).
Caveat for Phase A: all Phase A findings use the hand-coded 8-token DSL extracted by prior infrastructure. This is scaffolding, not the committed methodology. Phase B replaces the DSL with emergent motifs from BPE.

3.4 Heritability at the motif layer

What JSD is and why we use it. Jensen-Shannon divergence measures how different two probability distributions are. Here each agent has a distribution over motifs (what fraction of their tokens is FIND_FILE → FIND_FILE, what fraction is SEARCH → OPEN_SRC, etc.), and we compare agents pairwise. With log base 2, JSD is bounded in [0, 1]: 0 means two agents use motifs in identical proportions, 1 means their motif vocabularies don't overlap at all. Why JSD specifically? (a) it is symmetric — swapping the two agents gives the same answer, unlike KL divergence; (b) it is bounded, so numbers from different runs can be compared directly; (c) it is finite even when one agent never uses a motif the other relies on (KL would blow up). It is the natural question to ask of two agents' procedural repertoires: "how different are these two distributions?"
Heritability ordering is preserved and amplified when moving from atoms to motifs. GPT-family pair (GPT-4 × GPT-4o) has the tightest JSD at both granularities. Motif-level JSD shows a larger gap between same-family and cross-family agents than full-vocabulary JSD does.

3.5 Per-agent motif usage

Agents use systematically different motifs. Visible contrasts include: Claude uses FIND_FILE → FIND_FILE far more than GPT-4o; GPT-family agents use SHELL_RM → SUBMIT (cleanup before submission) while Claude barely does; GPT-4 dominates SEARCH → OPEN_SRC (standard investigative move).

3.6 Per-agent aggregate metrics

Beyond pairwise JSD, four agent-level aggregate metrics characterise each agent's procedural style: repertoire entropy, repertoire width, trajectory length, and compression ratio. All are derivable in one pass from the BPE-expressed corpus.

Agents have distinctive length profiles. GPT-4 is the most concise (21.4 atoms / 8.2 motifs per trajectory) — roughly half the length of the others. GPT-4o is the longest (39 atoms / 14 motifs) with the widest repertoire (84 motifs to cover 90% vs 66 for Claude and GPT-4) and the lowest compression (0.37, meaning heavy repeat structure). 4.1 What is a BPE merge?

A merge is a single step in BPE training. Each merge finds the most-frequent adjacent pair of tokens in the corpus, and binds that pair into a single new symbol. From that point on, every occurrence of that pair is treated as one token.

Concrete example from our training run — the first merge that was performed:

Pair found: EDIT_SRC_PY + EDIT_SRC_PY
Frequency across corpus:Most frequent adjacent pair (over 800 occurrences)
New merged symbol: EDIT_SRC_PY → EDIT_SRC_PY
Meaning:"Two source-file edits in a row" — a recognizable burst of editing activity

After this first merge, BPE looks for the most frequent pair in the updated corpus — which might now involve the new merged symbol. That is how longer motifs grow: once A→B is a single token, it can itself pair with neighbors to form A→B→C, etc.

We ran 124 merges total. Each merge adds one new symbol to the vocabulary and re-expresses the corpus to use that symbol where the pair appeared.

5. Sensitivity and robustness Appendix

Two robustness checks on the main heritability finding: (a) does the result hold across BPE vocabulary sizes, and (b) does it hold across task-difficulty slices?

5.1 BPE vocabulary size sweep

V=200 was a hyperparameter I picked. Sensitivity analysis across V ∈ {100, 125, 150, 175, 200, 225, 250, 300, 500} tests whether findings depend on the V choice.

Heritability ordering is robust across all tested V values. At every V in [100, 500], GPT-family pair (GPT-4 × GPT-4o) has the lowest JSD. The finding is not V-dependent.

Compression curve and V selection

V selection: V=200 by compression-elbow rule of thumb (first V where marginal compression gain per unit V drops below 0.001). The principled defense is the V-sweep itself: the heritability ordering holds across V ∈ [100, 500], so the finding does not hinge on the specific V chosen.

5.2 Difficulty-slice robustness

A second robustness check: bucket the 867 trajectories by task difficulty — the number of the three agents (0, 1, 2, or 3) that resolved the task — and recompute per-agent motif distributions and pairwise JSD at each value. Four buckets: 0/3 (n=573), 1/3 (n=131), 2/3 (n=97), 3/3 (n=66). Per-agent cell sizes stay above the N=10 floor throughout.

Heritability ordering is preserved at every difficulty value. GPT-family pair (GPT-4 × GPT-4o) has the lowest motifs-only JSD at all four values (0/3, 1/3, 2/3, 3/3). The main finding survives fine-grained stratification by task difficulty.
The heritability gap widens with success, not with difficulty. Motifs-only same-family vs cross-family gap: 0/3 = 0.019, 1/3 = 0.116, 2/3 = 0.064, 3/3 = 0.093. Opposite of the naive hypothesis that hard tasks would show more style signal. On 0/3 tasks every agent falls into the same exploration loops and style washes out; as more agents succeed, heritability becomes more visible in the motif repertoire. The 2/3 dip is consistent with small-sample noise (n=97).
Sample-size caveat. The 3/3 bucket has n=66 trajectories vs 573 for 0/3. Absolute JSD values rise with task easiness partly because small-sample motif-frequency estimates are noisy (JSD is biased upward on small samples). The load-bearing claims are the ordering (GPT-family lowest in every bucket) and the near-monotone gap widening with success. A permutation null is needed to establish whether the widening is above chance.

Qualitative finding: there is a clean procedural-phase progression across difficulty — 0/3 tasks are dominated by exploration motifs, 1-2/3 tasks by productive motifs, 3/3 tasks by short completion motifs. This is a phenomenon worth noting beyond the heritability question: task difficulty is visible in the motif repertoire, not just in pass/fail.

Permutation null (same-family advantage above chance): shuffle agent labels 1000 times, recompute the same-family vs cross-family dissimilarity gap each time, see where the observed gap falls in the null distribution.

5.3 Matched-pairs per-motif analysis

The aggregate pairwise dissimilarity number hides which specific motifs drive the difference. To isolate per-motif agent effects, we restrict to tied-outcome pairs (tasks where both agents A and B resolved — 99 such pairs). For each pair and each motif, compute Δ = freq(A) − freq(B). Task is held constant by construction, so the residual is an agent effect. Per-motif Wilcoxon signed-rank test + Benjamini-Hochberg FDR correction at 5%.

Only one token passes FDR at 5%, but effect directions replicate across cross-family pairs. With n=31-35 tied-outcome tasks per pair, individual Wilcoxon tests are underpowered after multiple-comparison correction. Only SUBMIT (in Claude vs GPT-4o) survives FDR 5% — GPT-4o uses SUBMIT ~12% more per token, reflecting its shorter trajectories after reaching resolution. More informative is the replication across the two cross-family panels: SHELL_RM → SUBMIT, EDIT_SRC_PY → ... → SUBMIT, and CREATE_REPRO_PY → ... all favor the GPT agent in both Claude-vs-GPT-4 and Claude-vs-GPT-4o. Two independent cross-family comparisons pointing the same direction is evidence beyond any one FDR test.
Power caveat. 99 tied-outcome pairs split across three agent-pairs gives 31-35 matched pairs per comparison. Detecting per-motif effects of |Δ| ≈ 0.03-0.05 at FDR 5% would need roughly 2-3× more tied-outcome pairs. Expanding the corpus (more agents, cross-benchmark) is the most effective way to strengthen this analysis. The effect-size rankings are informative even without individual FDR significance.

5.4 Whole-trajectory clustering

So far we have measured similarity at the motif-distribution level. A complementary question: do entire trajectories cluster into types? Encode each of the 867 trajectories as a normalized motif-frequency vector (one value per vocabulary item), then run HDBSCAN (density-based clustering, no k to pick) in the high-dim space with cosine distance. UMAP is used for visualization only, not for clustering.

Dense clusters are agent-typed, not task-typed. Of the 11 clusters HDBSCAN found, 9 have a single agent dominating ≥55% of membership (7 GPT-4o-dominated, 2 Claude-dominated, 0 GPT-4-dominated). Tasks within clusters are diverse (most clusters hit ≥10 distinct tasks). That pattern is what heritability predicts at the whole-trajectory level: when a trajectory is procedurally distinctive enough to join a dense cluster, the distinctiveness is an agent signature, not a task signature.
GPT-4 has zero dominated clusters — it lives in the "generic" population. GPT-4 is the most heavily represented agent in the 676-trajectory noise blob (38% of it), and does not dominate any of the 11 clusters. GPT-4's procedural style is "within-corpus average." GPT-4o, by contrast, has 7 distinctive clusters — its long-edit-bursts and reproducer-cleanup patterns show up as coherent types.
78% of trajectories are "generic". HDBSCAN returned 676 noise points — trajectories that can't be densely clustered at the motif-frequency level. This is consistent with the earlier pluralism finding: most SWE-bench Lite trajectories share common building-block motifs without forming distinctive procedural types. Only the 22% with genuinely distinctive procedural signatures produce dense clusters, and those clusters reveal agent structure.

5.5 Infrastructure cost and tokens

Each SWE-agent trajectory carries model_stats: tokens sent, tokens received, API calls, and dollar cost. Aggregated across 867 trajectories this gives an honest infrastructure-cost picture alongside the procedural analysis.

GPT-4 uses half the tokens of Claude or GPT-4o but is not the cheapest. Mean tokens sent per task: GPT-4 = 242k, GPT-4o = 494k, Claude-3.5 = 516k. Mean cost per task: Claude-3.5 = $1.62, GPT-4 = $2.51, GPT-4o = $2.53. Claude is the cheapest per task despite using the most tokens — Anthropic per-token pricing more than offsets the length disadvantage.
GPT-4o makes the most granular decisions. Mean API calls per task: GPT-4o = 39, Claude-3.5 = 33, GPT-4 = 22. GPT-4o is both long-running and finely-partitioned — every edit burst is many small API calls rather than one big one.
Failing a hard task is 40-60% more expensive than solving an easy one. On 0/3 tasks, GPT-4o averages 564k tokens sent, vs 250k on 3/3 tasks (2.3× more). Claude shows 580k vs 378k (1.5×). Cost rises proportionally. From an infra-cost perspective, the hardest tasks are also the most expensive, and agents flail longer before bailing — all three agents get progressively shorter as tasks become solvable.
Trajectory length is a near-perfect proxy for tokens burned. Pearson correlation between canonical atom count and tokens-sent: Claude r=0.96, GPT-4 r=0.98, GPT-4o r=0.95. Per-atom token slope: Claude ~18.5k, GPT-4 ~13k, GPT-4o ~13k — Claude uses ~40% more tokens per step, consistent with its longer per-step observations and thoughts.

Total burn for this pilot: 867 trajectories cost ~$1,925 total (Claude $469, GPT-4 $752, GPT-4o $704). Over 300 tasks and 3 agents, this gives the paper an empirical infrastructure-cost baseline: running an autonomous SWE-agent on a SWE-bench-Lite-scale task list costs roughly $2 per task per agent, averaged.

5.6 Step-level resources and efficiency

The aggregate cost picture hides where the spending happens. Attribute trajectory-level tokens proportionally across atoms, then roll up to each BPE motif. Now every procedural unit has a cost estimate alongside a success association (fraction of trajectories using it that resolved the task). That lets us ask: which procedures are efficient, which are wasteful?

Claude costs ~43% less per resolved task than GPT-4 and 36% less than GPT-4o. Cost per resolved task: Claude $10.20, GPT-4o $16.00, GPT-4 $17.91. Claude and GPT-4o resolve at the same rate (16%) but Claude costs $1.62/task vs GPT-4o's $2.53. GPT-4 pays the most per resolved task despite its compact trajectories — per-token pricing and slightly lower resolve rate both hurt.
The "cleanup-then-submit" pattern is the most efficient signature in the corpus. Top-resolving motifs: EDIT_SRC → RUN_REPRO → SHELL_RM → SUBMIT (30.1% resolve rate, 2× the base rate), SHELL_RM → SUBMIT (22.6%), FIND_FILE → OPEN_SRC (20.6%). The common element: short, decisive closing moves. An agent reaching this pattern has usually already solved the task; the motif is a marker of successful completion rather than a cause of success.
Long edit bursts are catastrophically wasteful. The top five wasteful motifs are all repetitive EDIT_SRC or NAV_SRC sequences of length 8-16+, costing 100-440k tokens per occurrence and resolving 0-9% of the time (vs 15.2% base rate). These are GPT-4o's characteristic "edit × 32" signature showing up as an anti-pattern: when the agent falls into a long repetitive edit burst, the odds of a solve drop sharply.

Why the "cleanup-submit is efficient" finding is load-bearing but needs framing. The association is correlational, not causal. SHELL_RM → SUBMIT appearing in a trajectory means the agent reached a point where it had something to submit — that is often already a solved task. We're not claiming that forcing agents to use this motif would improve solve rates. We're claiming that trajectories containing this motif are a procedurally identifiable "successful completion" class, and conversely, trajectories dominated by long edit bursts are an identifiable "flailing" class.

5.8 Semantic grouping: fix type × motif

Each of the 300 SWE-bench Lite tasks has a human-authored fix-type label (logic_fix, api_change, guard_clause, config_fix, and ten more; from output/datasets/swe_bench_lite_resolved/fix_types.json). Using fix type instead of instance-id as the grouping axis asks a sharper question: are procedural patterns universal across kinds-of-fix, or specialized?

Config fixes have a distinctively sparse procedural profile. The config_fix column is mostly blue: build-reproducer patterns are rare (ratio 0.38×), edit-run-reproducer patterns rarer still (0.17×), and cleanup-then-submit is under-used (0.73×). Agents handling a config change don't need runtime verification or iterative reproduction — they navigate, edit, submit. Procedural minimalism as a property of the task kind, not the agent.
Test-authoring patterns are fix-type-specific. CREATE_TEST_PY → EDIT_TEST_PY → RUN_PYTHON_TEST_PY peaks on the other bucket (3.07×) and on refactor; rare on guard_clause (0.39×) and string_fix (0.31×). Test-adding vs test-using is a procedural divide the fix-type axis surfaces cleanly; the instance-id axis blurs it.

Methodological note on the grouping axis: the earlier variance decomposition used instance_id (300 bins of ~3 trajectories each) and showed a strong "task dominates agent" pattern. The simpler fix-type grouping (13 bins of ~65 trajectories each) dampens that pattern substantially — most count features have ratios near 1.0 under fix_type. That means the original 300-bin effect was partly a sample-size artifact of small bins producing noisier means. The real semantic signal is in n_searches (2.1× by fix type) and edit_retry_rate (3.0×) — those features reflect what the task is about, not just which instance it was.

6. Headline findings Headline

  1. Task dominates agent at the feature-count layer. Raw trajectory counts (n_steps, n_edits, etc.) are 3–4× more explained by task than by agent identity. Agent style does not live at the count level.
  2. Within-task, rollout-level divergence is substantial and heritable. On tied-outcome pairs, same-family (GPT-4 × GPT-4o) action sequences differ by Levenshtein 0.37; cross-family pairs 0.51–0.52. Preliminary evidence for model-family heritability.
  3. Procedural pluralism is the dominant regime. 47% of tasks are procedurally permissive (high cross-agent divergence); only 5% are procedurally constrained. Most SWE-bench Lite tasks admit multiple valid procedural paths.
  4. BPE discovers interpretable procedural motifs. The learned vocabulary includes multi-step motifs like "build-reproducer" (CREATE_REPRO → EDIT_REPRO → RUN_PYTHON_REPRO) and "search-then-open." 60.5% of merged items are 3+ grams.
  5. Heritability strengthens from atoms to motifs. The JSD gap between same-family and cross-family agents widens from ~0.015 (full vocabulary) to ~0.06 (motifs only). Multi-step patterns carry more agent signal than individual actions.
  6. Motif-level agent differentiation is specific and nameable. Individual motifs distinguish agents: Claude uses FIND_FILE → FIND_FILE prolifically; GPT-family agents use SHELL_RM → SUBMIT (cleanup) while Claude does not.
  7. Findings are robust to BPE vocabulary size. Heritability ordering preserved across V ∈ [100, 500]; principled V selected via diminishing-returns analysis.
  8. Heritability also survives difficulty stratification, but the gap pattern is counter-intuitive. Same-family pair stays lowest at 0/3, 1/3, 2/3, and 3/3. Same-family vs cross-family gap widens near-monotonically with success: 0/3 → 0.019, 1/3 → 0.116, 2/3 → 0.064, 3/3 → 0.093. On 0/3 tasks all agents flail in similar exploration loops — style washes out. As tasks become solvable, procedural style signal emerges.
  9. Task difficulty is visible in the motif repertoire itself. Hard tasks are dominated by exploration motifs (FIND_FILE→FIND_FILE, SEARCH→SEARCH); mixed by productive motifs (EDIT→EDIT, build-reproducer); easy by short locate-then-act (FIND_FILE→OPEN, SHELL_RM→SUBMIT). A phenomenon independent of heritability.
  10. Heritability gap is above chance at every difficulty level. Permutation null with 1000 shuffled-label draws: aggregate p=0.001, 0/3 p=0.002, 1/3 p=0.001, 2/3 p=0.047 (marginal), 3/3 p=0.026. The same-family lead is not a sampling artifact.
  11. Agents have distinctive length, repertoire-width, and compression profiles. GPT-4 is most concise (~21 atoms/traj), GPT-4o longest (~39) with the widest repertoire (84 motifs to cover 90% vs 66). Claude compresses least (0.50). Nameable signatures from the novelty index: Claude = test-driven, GPT-4 = page-through-source, GPT-4o = long repetition bursts.
  12. Matched-pairs per-motif test: effect directions replicate across cross-family panels. On tied-outcome pairs (task controlled), only SUBMIT passes FDR 5% (Claude vs GPT-4o, Δ = +0.12 favoring GPT-4o). But the same direction for SHELL_RM → SUBMIT, EDIT_SRC_PY → ... → SUBMIT, and CREATE_REPRO_PY → ... appears in both cross-family comparisons independently — replication across independent comparisons is evidence beyond single-test FDR at n ≈ 33 per panel.
  13. Whole-trajectory clustering: dense clusters are agent-typed, and GPT-4 has none. HDBSCAN on motif-frequency vectors finds 11 dense clusters (22% of trajectories; 78% are in the generic "noise" population). 9 of the 11 clusters have a single agent dominating ≥55% of membership — 7 GPT-4o-dominated, 2 Claude-dominated, 0 GPT-4-dominated. GPT-4's style lives in the generic population; GPT-4o's distinctive patterns (long edit bursts, reproducer-cleanup) form coherent procedural types.
  14. Claude is cheapest despite using 2x the tokens of GPT-4. Mean cost per task: Claude $1.62, GPT-4 $2.51, GPT-4o $2.53. Mean tokens sent: Claude 516k, GPT-4 242k, GPT-4o 494k. Claude's per-token pricing more than offsets its longer trajectories. Failing a 0/3 task is 40-60% more expensive than solving a 3/3 task — cost rises with difficulty as agents flail longer before giving up. Trajectory length explains 90%+ of variance in token burn (Pearson r = 0.95-0.98 across agents).
  15. Cost per resolved task: Claude $10.20, GPT-4o $16.00, GPT-4 $17.91. Claude is 43% cheaper per resolved task than GPT-4, 36% cheaper than GPT-4o. The "cleanup-then-submit" motif family is the most efficient signature (resolve rate 22-30%, 1.5-2× the 15.2% base rate). Long repetitive edit bursts are catastrophically wasteful (0-9% resolve rate, 100-440k tokens per occurrence) — the GPT-4o "edit × 32" signature is a direct anti-pattern.

7. Implications Headline

For evaluation

A single pass/fail number hides most of what separates agents. Two agents can both solve a task and still walk very different procedural paths (Levenshtein 0.37 within a family, 0.52 across) — that's an evaluation signal thrown away. Benchmarks that deliberately stratify tasks by procedural permissiveness (permissive vs constrained) would reveal when agent style matters and when it's washed out by the task shape.

For agent design

Model-family heritability suggests procedural style is a transferable property of the backbone, not just an artifact of scaffolding (because all three agents share the SWE-agent scaffold, yet family structure still appears). That implies the training distribution of the backbone shapes procedural repertoire in a way that survives a fixed harness. A stronger test requires factorial scaffold × backbone variation (see next steps).

For tools built on motifs

Products like Cursor's "library of procedures" or Devin's playbooks are betting that reusable procedural units exist and can be named. This pilot is empirical support for that bet: BPE — a method with zero domain knowledge — discovered motifs that map to recognizable practices ("build-reproducer," "search-then-open," "locate-then-open"). The specific 124 motifs here are candidates for a procedure library.

For research methodology

Bottom-up motif discovery works. We did not hand-design a DSL of procedural units; canonicalize-then-BPE found them from 867 real trajectories. This replaces the usual pattern of "come up with a taxonomy, then score agents against it" with "let the corpus reveal the taxonomy." The finding that 60.5% of merged items are 3+ grams — not just bigrams — means multi-step structure was there to be found.

For the larger research agenda

This fits the umbrella of procedural knowledge preservation: if we can capture how agents solve problems — not just whether they do — we get a richer object for comparison, transfer, and critique than raw outputs alone. Paper 1 (Procedural Diff) studies patches; Paper 2 (this work) studies action sequences; a future Paper 3 would study regression / drift in procedure over time.

12. Glossary Appendix

Action
One step in an agent's trajectory — a shell-like command issued by the agent (e.g., edit 1:3 …, search_file "DataDocumenter", submit).
Trajectory
The full ordered sequence of actions one agent took on one task. A .traj file is one trajectory.
Canonical atom
A normalized single-token representation of one action. Type-tagged by file kind (_SRC_PY, _TEST_PY, _REPRO_PY, _CONFIG, _DOC) and verb (EDIT, OPEN, SEARCH, RUN_PYTHON, …). Example: EDIT_SRC_PY, RUN_PYTHON_REPRO_PY. 76 unique atoms cover 99.9% of the corpus.
BPE (Byte-Pair Encoding)
A compression-style algorithm from Sennrich et al. 2016 (originally for subword tokenization). Iteratively: find the most-frequent adjacent pair in the corpus, replace every occurrence with a new single symbol, repeat. Used here to discover procedural motifs from canonical atom sequences.
Merge
One step of BPE training. Binds one adjacent pair into one new symbol, grows vocabulary by 1, re-expresses the corpus to use it. We ran 124 merges (V=200 target).
Motif
A BPE-learned multi-atom token. Anything in the vocabulary that is not an atom. Motifs can be 2-grams (FIND_FILE → FIND_FILE) up to 32-grams in our run.
Vocabulary size (V)
Target total vocabulary after BPE training = atoms + merged motifs. V=200 means ~76 atoms + 124 motifs.
Compression ratio
(BPE token count) ÷ (canonical atom count), averaged over the corpus. Lower = more compression. At V=200, ratio ≈ 0.41: BPE expresses the corpus with 41% as many tokens.
JSD (Jensen-Shannon divergence)
A symmetric, bounded distance between two probability distributions. With log base 2 it lives in [0, 1]: 0 = identical, 1 = disjoint support. We compute it between per-agent motif-usage distributions to ask "how differently do these two agents use motifs?" Chosen over KL because it is symmetric and finite even when distributions have zero mass on each other's support.
Levenshtein distance (normalized)
Minimum edit-operation count between two sequences, divided by the length of the longer. Used pairwise on tied-outcome trajectories to measure how different two agents' action sequences are on the same task.
Tied-outcome pair
A pair of (agent_A, agent_B) on the same task where both agents resolved the task. 99 such pairs in the corpus. Controls for task difficulty when comparing procedural paths.
Procedurally permissive
Describing a task where the agents that attempted it took substantially different action sequences (mean pairwise divergence ≥ 0.60). 47% of SWE-bench Lite tasks are permissive.
Procedurally constrained
Opposite of permissive: agents converged on a similar action path (mean pairwise divergence ≤ 0.30). Only 5% of tasks.
Heritability (in this context)
Borrowed from behavioral genetics: the extent to which agent behavior tracks model family (GPT vs Claude) rather than idiosyncratic run variation. Here: same-family pairs (GPT-4 × GPT-4o) show smaller procedural distance than cross-family pairs.
MDL (Minimum Description Length)
Rissanen's principle: prefer the hypothesis (here: vocabulary size) that minimizes total code length = corpus bits + model bits. We tried MDL to pick V; the corpus-encoding cost dominates in our regime, so MDL decreases monotonically and does not select an interior V.
Variance decomposition
One-way ANOVA: for each per-trajectory feature, partition variance into agent-explained vs task-explained. Told us 35–48% task vs 1–13% agent at the count level.
SWE-bench Lite
A 300-instance subset of SWE-bench (real GitHub issue → patch) benchmarked across SWE-agent backbones. Primary corpus for this pilot.
Phase A / Phase B
Phase A uses the pre-extracted hand-coded 8-token DSL (scaffolding only). Phase B is the committed methodology: canonicalize-then-BPE on raw .traj files.

13. Cross-scaffold universality (2026-04-25) Appendix

Same problem set (SWE-bench Lite), same backbone (Claude 3.5 Sonnet), different scaffold (SWE-agent vs Agentless). The variable that changes is the scaffold's architectural commitment: SWE-agent gives the LLM autonomy to choose tool calls; Agentless takes that autonomy away and runs a fixed pipeline (file localization sub-stages, four parallel repair samples, regression-test selection plus reproducer generation).

13.1 The empirical Agentless pipeline

300 Agentless logs scanned. 12 phase markers appear in every log in the same order. The pipeline is fully deterministic at the structural level.

13.2 β and γ extractors

Two extractors built and run on all 300 logs:

  • β extractor: maps Agentless events onto the existing 76-atom SWE-agent canonical alphabet. Atoms with no analog simply do not appear.
  • γ extractor: emits Agentless-native atoms that preserve scaffold-internal structure (LOCALIZE_FILES, LOCALIZE_EMBED, LOCALIZE_ELEMENTS, LOCALIZE_LINES, REPAIR_SAMPLE_1-4, REGRESSION_SELECT, REPRO_GEN).

Per-log averages across 300 logs: mean β length 20.75 atoms; mean γ length 10.06 atoms; β/γ ratio 2.05. The ratio reflects per-file expansion (FIND_FILE atoms multiply per file mentioned in localizer outputs).

13.3 The paired finding

Finding 13. Phase categories (localize / repair / verify) are scaffold-invariant. Phase emphasis is scaffold-determined. The categorical level transfers; the proportional level reflects each scaffold's architectural commitment about agent autonomy. This is a more nuanced universals claim than "phase shape transfers cleanly" and is honestly defensible.

Folds into the procedural-Clio paper as part of phenomenon 3 (cultural universality). Specifically: cross-scaffold universals at the categorical level, with the empirically-identified scaffold-emphasis variable as the source of cross-scaffold variation.

16.4 Paper 4 (deferred): procedural budget under controlled scaffold

Sharpened thesis (added 2026-04-25). Are procedural styles preferences or are they load-bearing for capability? If a model has a preferred style (Claude 3.5 is measurably more grepy than GPT-4o; Agentless is dramatically grepy by architectural design) and you constrain that style at fixed budget, does its capability degrade? If yes, the style was load-bearing for that model. If no, the style was preference and the model can adapt.

This reframes the original "DSPy programmable shape" trajectory from a methodology demonstration into an intervention study with a falsifiable hypothesis. The mechanism (declarative scaffold language via DSPy idioms) is the same; the empirical claim is sharper.

Headline empirical setup.

  1. Pick a procedural axis to constrain. Localize-fraction is the obvious one given today's β/γ data. Other candidates: number of repair iterations, presence of test-running, trajectory length.
  2. Pick a budget to equalize. Total tokens consumed is the standard fairness measure; total tool calls is more directly procedural.
  3. Build constrained DSPy programs at multiple constraint levels (e.g., localize ≤ 10%, ≤ 25%, ≤ 50%) at the same total budget.
  4. Run on a small instance set (50 SWE-bench Lite instances is enough for a pilot) with multiple backbones at each constraint level.
  5. Measure pass rate per (backbone, constraint) cell. If pass rate degrades faster for some backbones than others, style was load-bearing for the faster-degrading ones.

Soft evidence already in hand from today's β/γ. Across SWE-agent backbones, localize fractions are 8% (GPT-4o), 11% (GPT-4), 13% (Claude 3.5). Across scaffolds, Agentless is at 50-60% localize. If you forced everyone to 10% localize at fixed budget:

  • GPT-4o would be roughly unchanged.
  • GPT-4 mildly constrained.
  • Claude 3.5 (SWE-agent) meaningfully constrained.
  • Agentless (Claude 3.5) severely constrained.

The performance differential under that constraint IS the experiment. The hypothesis is "the more constrained, the larger the performance hit, conditional on style being load-bearing."

Why this matters. Today's leaderboards mix capability and procedure. A study that holds budget constant and varies allowed procedures gives you the "capability under constraint" axis that current evaluation does not. It directly informs the Cursor pluralism story: if styles are mostly preferences, personalization is free; if styles are load-bearing, personalization narrows. It also speaks to fairness in agent comparison (different models burn wildly different compute on the same task; equalizing budget is an underserved control).

Cost. 4 backbones × 4 constraint levels × 50 instances ≈ a few hundred LLM calls per cell, in the range of $50-200 per backbone. Real but tractable.

Status. Deferred until after procedural-Clio lands. Roughly 4-6 weeks of build plus run plus write when activated.

Venue. EMNLP via ACL ARR (LM-systems track) or COLM. The cognitive-scaffolding theoretical framing (Wood, Bruner, Ross 1976; Vygotsky) gives the paper intellectual anchoring beyond the framework demo.

Honest caveats.

  • Defining "constraint" precisely is hard for free-form scaffolds. Easier in Agentless because phases are explicit.
  • Budget equalization is interpretation-sensitive (tokens, calls, wall time, dollars give different stories).
  • Pass rate is a noisy metric on 50-instance sets; either need more instances or a continuous metric to reduce noise.
